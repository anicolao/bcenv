# Experiment records

Read the pinned year manifest and trial specification first. Stop before a trial
if any required tool or service is marked unavailable. Never ask the competitor
to repair an incomplete environment.

Work only in assigned competitor/ and work/ directories. Before changing your
candidate, record a concrete behavioral prediction under work/experiments/.
Record commands and artifact IDs, then compare replay evidence against that
prediction. Describe contradictory or absent evidence honestly. A negative
result is valid evidence. Keep observation separate from explanation.

Use a new output directory for each attempt. Preserve failed attempts. Do not
alter compiled artifacts in place; rebuild changed sources. Package the exact
verified candidate selected for submission. Follow the year-specific tooling
skill. Never equate a queue receipt with execution or process success with a win.

This release is builder readiness work. The exact kickoff is included for future
review, but no fresh competitor trial is enabled until all readiness gates and
isolation/budgets are configured. Do not infer permission to submit externally.
